## Что это такое

`llm-wiki` — это Skill, работающий в Claude Code, который принимает необработанные документы любого формата (PDF, DOCX, PPTX, XLSX, Markdown, изображения) в структурированную Wiki и автоматически строит интерактивный граф знаний (`graph.html`).

Он реализует философию управления знаниями, предложенную Карпати: **знания синтезируются в момент загрузки, а не в момент запроса**. Каждый раз, когда добавляется новый документ, LLM автоматически извлекает ключевые моменты, устанавливает перекрёстные ссылки, отмечает противоречия и обновляет сводное резюме — позволяя базе знаний расти экспоненциально с каждой загрузкой.

Принципиальное отличие от RAG: RAG загружает сырые документы в векторное хранилище и собирает ответы на лету в момент запроса; llm-wiki компилирует знания в долговечные wiki-страницы в момент загрузки, так что запросы читают уже синтезированные выводы.

## Структура Директорий

```
<wiki-root>/
├── SCHEMA.md                    # Определение предметной области + таксономия тегов + соглашения
├── index.md                     # Оглавление разделов, одна строка на страницу
├── overview.md                  # Живой синтез по всем источникам
├── log.md                       # Журнал операций только для добавления (автоматическая ротация при >500 записей)
│
├── raw/                         # Неизменяемые исходные источники
│   ├── articles/                # Веб-статьи, вырезки
│   ├── papers/                  # PDF, arxiv-статьи
│   ├── transcripts/             # Заметки с совещаний, интервью
│   ├── assets/                  # Изображения, диаграммы
│   └── <custom-topic>/          # Пользовательские тематические директории
│
├── sources/                     # Страница-резюме для каждого исходного документа
├── entities/                    # Страницы сущностей (люди/компании/проекты/продукты)
├── concepts/                    # Страницы концепций (концепции/фреймворки/методологии)
├── comparisons/                 # Страницы сравнительного анализа
├── queries/                     # Архив результатов ценных запросов
├── archive/                     # Архив устаревших страниц
│
└── graph/
    ├── graph.json               # Данные узлов + рёбер
    └── graph.html               # Автономная визуализация на основе vis.js
```

## Справочник Команд

| Команда | Назначение |
|---|---|
| `wiki-config workspace <path>` | Установить путь к рабочему пространству wiki |
| `wiki-config show` | Просмотр текущей конфигурации и состояния директорий |
| `wiki-input <path> [--topic <slug>]` | Загрузить любой файл (автоматически архивируется в `raw/<topic>/`) |
| `wiki-ingest <file>` | Загрузить файл, уже находящийся в `raw/` |
| `wiki-query: <вопрос>` | Запросить базу знаний, синтезировать ответ |
| `wiki-lint` | Проверить изолированные страницы, битые ссылки, противоречия |
| `wiki-graph` | Построить интерактивный граф знаний (`graph.html`) |

**Рекомендуется для ежедневного использования: `wiki-input`** — принимает локальные или удалённые пути, автоматически копирует в `raw/<topic>/` перед загрузкой. Ручное управление директорией `raw/` не требуется.

## Рабочий Процесс

### Загрузка (Ingest)

При загрузке документа LLM последовательно выполняет:

1. Чтение `SCHEMA.md` для понимания соглашений предметной области и таксономии тегов
2. Мультимодальное извлечение контента (PDF/DOCX/PPTX/XLSX/изображения → Markdown)
3. Запись `sources/<slug>.md` (резюме, ключевые моменты, важные цитаты)
4. Обновление `index.md` и `overview.md`
5. Создание или обновление страниц `entities/` и `concepts/`
6. Создание или обновление страниц `comparisons/`, если источник содержит сравнительную информацию
7. Отметка противоречий с существующим контентом
8. Добавление журнала операций в `log.md`

### Запрос (Query)

Читает `index.md` для идентификации соответствующих страниц, синтезирует ответ с встроенными ссылками в формате `[[PageName]]`. Существенные ответы могут быть архивированы в `queries/<slug>.md`.

### Граф Знаний (Graph)

Извлекает явные wikilinks (`EXTRACTED`) и семантические связи, выведенные ИИ (`INFERRED`, достоверность ≥ 0.5) между страницами, генерирует автономный `graph.html` без зависимостей с раскраской по типу узлов и группировкой по сообществам.

## Поддерживаемые Форматы

| Формат | Метод Извлечения |
|---|---|
| `.md` `.txt` | Прямое чтение |
| `.pdf` | pdfplumber (текст + таблицы) |
| `.docx` | python-docx (тело + заголовки + таблицы) |
| `.pptx` | python-pptx (заголовки + тело + заметки) |
| `.xlsx` `.csv` | pandas (преобразование в таблицы Markdown) |
| `.png` `.jpg` `.jpeg` `.webp` `.gif` `.bmp` | Claude vision (мультимодальный) |

## Детали Мультимодальной Поддержки

`llm-wiki` использует нативные мультимодальные возможности Claude для понимания содержимого изображений — не просто OCR-распознавание текста, а полное семантическое понимание диаграмм, графиков и скриншотов.

### Прямая Загрузка Файлов Изображений

Передайте любой файл изображения напрямую в `wiki-input` или `wiki-ingest`. Claude прочитает изображение и преобразует его в структурированный Markdown перед запуском стандартного рабочего процесса загрузки:

```bash
wiki-input ~/скриншоты/архитектурная-диаграмма.png --topic system-design
wiki-input ~/фото/сессия-на-доске.jpg --topic meetings
```

**Что Claude извлекает из изображений:**
- **Диаграммы & графики** — ряды данных, метки осей, тренды, числовые значения
- **Схемы & блок-схемы** — узлы, рёбра, связи, направление потока
- **Скриншоты** — структура UI, видимый текст, контекст макета
- **Рукописные заметки / доски** — расшифрованный текст и нарисованные структуры
- **Таблицы в изображениях** — восстанавливаются как таблицы Markdown
- **Смешанный контент** — сфотографированные или отсканированные документы с текстом и рисунками

### Изображения, Встроенные в Документы

При загрузке файлов PDF, DOCX или PPTX с встроенными изображениями соответствующий инструмент извлечения захватывает весь текстовый контент. Для рисунков и диаграмм, критически важных для понимания, когда одного извлечения текста недостаточно, повторно загрузите их как отдельные файлы изображений.

### Поддерживаемые Форматы Изображений

| Формат | Примечания |
|---|---|
| `.png` | Без потерь; идеально для скриншотов, диаграмм |
| `.jpg` / `.jpeg` | Фотографии, отсканированные документы |
| `.webp` | Оптимизированные для веба изображения |
| `.gif` | Анализируется первый кадр (статичный контент) |
| `.bmp` | Несжатый растровый формат |

### Мультимодальный Конвейер Извлечения

Весь контент изображений проходит тот же конвейер загрузки, что и текстовые документы — изображение просто сначала конвертируется в Markdown:

```
Файл Изображения
    │
    ▼
Claude Vision (инструмент Read)
    │  Извлекает: текст, структуру, данные, связи
    ▼
Описание Markdown
    │
    ▼
Стандартный Рабочий Процесс Загрузки (Шаги 2–10)
    │  sources/ entities/ concepts/ index/ overview/ log/
    ▼
Страницы Wiki + Граф Знаний
```

## Быстрый Старт

```bash
# 1. Установить рабочее пространство wiki
wiki-config workspace ~/my-wiki

# 2. Загрузить первый документ
wiki-input ~/Downloads/paper.pdf --topic papers

# 3. Запрос
wiki-query: Каков основной вклад этой статьи?

# 4. Построить граф знаний
wiki-graph
```
